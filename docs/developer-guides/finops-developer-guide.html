💰 FinOps — Agent Cost Intelligence Developer Guide

FlowAMP · How real per-agent cost tracking works today, and what's still a production-hardening TODO

Context: The FlowAMP dashboard has a FinOps tab showing total monthly spend, cost per invocation, utilization, projected overrun, a 30-day spend trend, a Cost by Component breakdown, and a per-agent cost table. This is no longer static seed data — spend is REAL, pulled daily from AWS Cost Explorer by the finops-collector Lambda and written back as COST# ledger rows the UI reads. This guide documents how that pipeline actually works in the repo today, and flags the pieces that are still production-hardening TODOs (token-level model cost, forecast, anomaly detection).

How It Works Today (End to End)

  1. Tagging. The CDK stack applies the flowamp:agentId cost-allocation tag to every taggable resource. The stack-level value is platform; each AgentCore runtime is tagged with its specific agent id so Cost Explorer can attribute spend per agent.
  2. Tag activation. A CFN custom resource (cost-tag-activator) best-effort activates flowamp:agentId as a cost-allocation tag in Billing (management/payer account only).
  3. Daily collection. finops-collector runs daily at 03:00 UTC, queries Cost Explorer GetCostAndUsage grouped by the flowamp:agentId tag, and writes one COST#<date> row per agent with source: cost-explorer.
  4. Read + render. The UI calls GET /costs → data-handler.get_costs, which scans the COST# rows for the last N days. renderFinOps() aggregates them into the total, trend chart, and Cost-by-Component panel, and shows a ● Live · Cost Explorer badge.

No synthetic fallback: until the tag is activated and CE backfills (~24–48h), the collector writes nothing and the UI simply shows no live cost. Demo/seed cost is only ever present if you explicitly opt in with -c seedSampleData=true (labelled ◐ Demo data in the UI).

Data Model

FlowAMP uses a single DynamoDB table (AgentTable) with a composite key: partition key agentId, sort key sk. Cost is not a monthlyCost field on the agent's INFO row — it lives in its own ledger rows keyed sk = "COST#<YYYY-MM-DD>". Each agent gets one COST# row per day.

// INFO row — the canonical agent record (no cost fields)
{ "agentId": "flowamp_management_agent", "sk": "INFO", "status": "active", "runtimeArn": "arn:aws:bedrock-agentcore:..." }

// COST#<date> row — one per agent per day, written by finops-collector
{
  "agentId":        "flowamp_management_agent",
  "sk":             "COST#2026-07-05",
  "date":           "2026-07-05",
  "status":         "final",
  "source":         "cost-explorer",
  "totalCost":      12.481200,               // UnblendedCost for the day (Decimal, 6dp)
  "costByComponent": {
    "modelInference": null,                  // NOT tracked yet — needs OTEL token cost
    "agentCompute":   3.204100,              // Lambda + EC2 compute
    "toolExecution":  1.010000,              // Step Functions + API Gateway
    "storage":        0.442000               // S3 + DynamoDB

The Cost-Allocation Tag: flowamp:agentId

Cost Explorer can only group by a tag once that tag key is activated in Billing. FlowAMP uses the tag key flowamp:agentId (defined once in team-stack.ts as COST_TAG_KEY).

// team-stack.ts — one tag key, applied stack-wide
const COST_TAG_KEY = "flowamp:agentId";

// Stack-level default: every taggable resource gets flowamp:agentId=platform.
// Applied regardless of the enableCostExplorer flag so tag history accrues early.
cdk.Tags.of(this).add(COST_TAG_KEY, "platform");

// Per-agent override: tags applied deeper in the construct tree win, so each
// agent gets its specific agent id (this is what CE groups by). The management
// agent is a HARNESS, tagged via its CfnHarness `tags` property plus the
// stack-level Tags aspect; the scanners are runtimes.
cdk.Tags.of(harness).add(COST_TAG_KEY, "flowamp-management-agent");
cdk.Tags.of(discoveryScanner).add(COST_TAG_KEY, "flowampDiscoveryScanner");
cdk.Tags.of(complianceScanner).add(COST_TAG_KEY, "flowampComplianceScanner");

Activating the tag (one-time)

Activation is a Billing / payer-account operation. The cost-tag-activator CFN custom resource attempts it automatically on deploy:

# cost-tag-activator/index.py — best-effort activation
ce = boto3.client("ce", region_name="us-east-1")   # CE is ALWAYS us-east-1
ce.update_cost_allocation_tags_status(
    CostAllocationTagsStatus=[{"TagKey": "flowamp:agentId", "Status": "Active"}]
)
  • This only succeeds from the organization management (payer) account. In a member/linked/sandbox account the call is AccessDenied — expected. The custom resource never fails the stack; it logs that the tag must be activated manually in the Billing console and returns SUCCESS.
  • Two AWS-side delays even on success: the tag key must first appear in Billing (up to ~24h after the first tagged resource is created), and CE then needs up to another ~24h before it returns data grouped by it — roughly 24–48h before real spend shows up.

The Collector: finops-collector/index.py

Runs daily on an EventBridge schedule (gated by the enableCostExplorer flag, which defaults to ON). For the previous UTC day it:

  1. Enumerates active agents that have a runtime ARN (skips placeholder registrations so it doesn't write $0 noise) — a single-table Scan filtered to sk = "INFO".
  2. Runs four Cost Explorer queries in parallel — one account-wide total plus three per-service-group component queries — all grouped by the flowamp:agentId tag.
  3. Writes one COST#<date> row per agent with source: 'cost-explorer'. It's idempotent: an existing final row for the day is left as-is.

def _ce_query(target_date, services):
    """One CE GetCostAndUsage grouped by flowamp:agentId. services=None → total."""
    end = (date(target_date) + timedelta(days=1)).strftime("%Y-%m-%d")
    ce = boto3.client("ce", region_name="us-east-1")     # CE is always us-east-1
    tag_filter = {"Tags": {"Key": "flowamp:agentId"}}
    cost_filter = tag_filter if services is None else {
        "And": [tag_filter, {"Dimensions": {"Key": "SERVICE", "Values": services}}]
    }
    resp = ce.get_cost_and_usage(
        TimePeriod={"Start": target_date, "End": end},
        Granularity="DAILY",
        Metrics=["UnblendedCost"],
        Filter=cost_filter,
        GroupBy=[{"Type": "TAG", "Key": "flowamp:agentId"}],

Error handling (per AWS docs)

  • The CE endpoint is always us-east-1 regardless of the stack region.
  • DataUnavailableException / empty result = the normal "not ready yet" case (tag not activated, or no spend) → the collector writes nothing and returns a reason.
  • LimitExceededException = throttling → re-raised so EventBridge retries.

CDK: FinOps Collector Wiring

From team-stack.ts, inside if (enableCostExplorer) (default ON; disable with -c enableCostExplorer=false):

const enableCostExplorer = this.node.tryGetContext("enableCostExplorer") !== "false"; // default ON
const COST_TAG_KEY = "flowamp:agentId";

if (enableCostExplorer) {
  const finopsCollectorFn = new lambda.Function(this, "FinopsCollectorFn", {
    runtime: lambda.Runtime.PYTHON_3_12,
    handler: "index.handler",
    code: lambda.Code.fromAsset(path.join(assetsSrc, "lambda", "finops-collector")),
    environment: { AGENT_TABLE_NAME: agentTable.tableName, COST_TAG_KEY },
    timeout: cdk.Duration.seconds(120),
  });
  agentTable.grantReadWriteData(finopsCollectorFn);

  // Cost Explorer is account-wide; ce:* actions do not support resource scoping.
  finopsCollectorFn.addToRolePolicy(new iam.PolicyStatement({
    actions: ["ce:GetCostAndUsage"],
    resources: ["*"],
  }));

  // Run daily at 03:00 UTC — a few hours after CE finalizes the prior UTC day.
  new events.Rule(this, "FinopsCollectorSchedule", {
    schedule: events.Schedule.cron({ minute: "0", hour: "3" }),
    description: "Collect real per-agent spend from Cost Explorer (flowamp:agentId tag)",
  }).addTarget(new targets.LambdaFunction(finopsCollectorFn));

  // Best-effort activation of the cost-allocation tag (management account only).
  const costTagActivatorFn = new lambda.Function(this, "CostTagActivatorFn", {
    runtime: lambda.Runtime.PYTHON_3_12,
    handler: "index.handler",
    code: lambda.Code.fromAsset(path.join(assetsSrc, "lambda", "cost-tag-activator")),
    environment: { COST_TAG_KEY },
    timeout: cdk.Duration.seconds(60),
  });
  // Cost Explorer is account-wide; ce:* actions do not support resource scoping.
  costTagActivatorFn.addToRolePolicy(new iam.PolicyStatement({
    actions: ["ce:UpdateCostAllocationTagsStatus", "ce:ListCostAllocationTags"],
    resources: ["*"],
  }));
  const costTagProvider = new cr.Provider(this, "CostTagActivatorProvider", {
    onEventHandler: costTagActivatorFn,
  });
  new cdk.CustomResource(this, "CostTagActivation", { serviceToken: costTagProvider.serviceToken });
}

Note the minimal IAM: the collector is granted only ce:GetCostAndUsage (not forecast or anomaly actions), and the activator only ce:UpdateCostAllocationTagsStatus / ce:ListCostAllocationTags. Broadening these is part of wiring the TODO widgets below.

How the UI Reads Cost

The UI calls GET /costs?days=30 → data-handler.get_costs(), which scans the ledger rows:

def get_costs(days=30):
    """Raw COST# ledger rows for the last N days (sk='COST#<YYYY-MM-DD>')."""
    cutoff = (date.today() - timedelta(days=days - 1)).strftime('%Y-%m-%d')
    # begins_with('COST#') keeps this off INFO/EVENT rows; the gte floor bounds the window.
    flt = Attr('sk').begins_with('COST#') & Attr('sk').gte('COST#' + cutoff)
    # ... paginate the scan, return the raw rows ...

In agent-management.html, renderFinOps() consumes those rows (liveCostRows):

  • Source badge: if any row has source === 'cost-explorer' → ● Live · Cost Explorer; else if demo-seed → ◐ Demo data; else hidden.
  • Total spend: sum of totalCost across live rows (real AWS spend), not the inline finopsData array (which is empty by default — no synthetic fallback).
  • Cost by Component: aggregates costByComponent; modelInference renders as "not tracked" when null rather than a fake number.
  • Trend chart: live rows grouped by date, summed per day.

Why Agent FinOps Is Different

💡 Key Insight: FinOps for AI agents differs from traditional cloud FinOps because the dominant cost is model tokens, not compute. A single invocation that generates a long response can cost more than the runtime hosting it. FlowAMP tracks the compute/tooling/storage components today via Cost Explorer service grouping, but the token component (modelInference) is deliberately left null until OTEL token ingestion is added — the honest signal for chargeback. The tagging strategy is the foundation: without the flowamp:agentId cost-allocation tag on every resource (and activated in Billing), Cost Explorer can't attribute spend per agent. The model FlowAMP agents run on is us.anthropic.claude-sonnet-4-6.
